# Implementation Plan

- [ ] 1. 先行条件確認と検証基盤の準備
- [ ] 1.1 上流受口の実装状態確認と合否記録
  - 推論上限変更の受口（`FrameThrottle.setLimit(_:)`・fps側で追加）とセンサー頻度設定の受口（受動公開pull一本化・motion側で修正）が実装済みか確認する
  - motion-frequencyの完了を確認し、未完了の場合は本機能の実装に入らず先行完了を待つ旨を記録する
  - `PostureSessionManager.swift` の適用順（fps→mainactor→motion→dim）に従い、本specの編集が最後であることを確認する
  - 未実装の受口がある場合は本機能の実装に入らず先行完了を待つ旨を記録する
  - 確認結果の合否記録が参照可能な状態で残る
  - _Requirements: 2.1, 3.1_

- [ ] 2. 段階管理と頻度連動の実装
- [ ] 2.1 (P) 省電力段階方針の実装
  - 通常・暗転・長時間不在の段階定義と遷移判定・復帰則・不在しきい値（単位: 秒・基準時計: 単調時刻系 `TimeInterval`）を実装する
  - `tick(isPersonDetected:now:)` の `now` は `TimeInterval`（`FrameThrottle`／MainHopGateと同一時計）とし、`Date` を用いない
  - 段階遷移の入力を暗転操作と検出結果のみに限定する
  - カメラなしで遷移則を検証できる状態になる
  - _Boundary: DimPowerPolicy_
  - _Depends: 1.1_
  - _Requirements: 2.1, 2.2, 3.1, 8.1_
- [ ] 2.2 (P) 推論上限変更の受口利用（追加は行わない）
  - 前提インターフェース `FrameThrottle.setLimit(_:)`（fps側で追加済みであること・tasks 1.1で確認）を利用するのみとし、本specでは受口追加を行わない
  - 既存の判定則・計数・初期化の振る舞いを変えない
  - 上限切替え後に判定が継続できる状態になる
  - _Boundary: PostureSessionManager（切替え結線のみ。FrameThrottle非編集）_
  - _Depends: 1.1_
  - _Requirements: 2.1, 2.2, 2.3_
- [ ] 2.3 段階方針の単体検証
  - 段階遷移（通常→暗転→長時間不在）・人物再検出時の戻り・解除時の復帰を検証する
  - 不在しきい値の境界動作を検証する
  - 全ての遷移則が単体検査で確認できる状態になる
  - _Requirements: 2.1, 2.2_
- [ ] 2.4 上限変更受口の単体検証と既存回帰
  - 上限変更の境界動作と変更直後の判定継続を検証する
  - 既存の間引き判定・計数・初期化の回帰を再実行する
  - 新規・既存の検証が全て成功する状態になる
  - _Requirements: 2.1, 2.2, 2.3, 2.4_

- [ ] 3. 段階切替えの結線と復帰時戻し
- [ ] 3.1 暗転移行・解除経路への切替え結線
  - 暗転移行時に推論上限・取得頻度の低下指示を適用する
  - 長時間不在段階への遷移時に更なる低下指示を適用する
  - 段階別の低下が動作中の管理層で確認できる状態になる
  - _Depends: 2.1, 2.2_
  - _Requirements: 1.3, 2.1, 2.3, 3.1, 3.3_
- [ ] 3.2 復帰時戻しの一本化と戻し忘れ防止
  - 暗転解除・監視開始・フォアグラウンド復帰の各経路で上限・頻度の通常戻しを行う
  - 輝度復元と上限・頻度戻しの順序を保ち、センサー稼働状態を変更しない
  - 全解除経路で戻しが完了することが結合検証で確認できる状態になる
  - _Requirements: 1.3, 2.3, 3.3, 6.1_
- [ ] 3.3 不在駆動の結線と既存則の回帰
  - 検出結果の受取り点に不在駆動を付随させ、判定ロジックへの介入を行わない
  - 3秒確定則・閾値・代替鎖・通知仕様の不変を回帰で確認する
  - 輝度制御・スリープ抑止・起停則の不変を回帰で確認する
  - 監視継続と既存則の維持が結合検証で確認できる状態になる
  - _Requirements: 1.1, 1.2, 2.2, 2.4, 3.2, 4.1, 4.2, 4.3, 4.4, 6.2, 6.3_

- [ ] 4. 評価と実測記録
- [ ] 4.1 カメラ停止の評価観点の記録と停止経路の不存在確認
  - 復帰時間・再開時の検出遅延・再開コストの評価観点と記録形式を残す
  - 評価未完了の状態で停止経路が存在しないことを確認する
  - 評価記録が参照可能な状態で残り、停止実装が含まれない状態になる
  - _Requirements: 5.1, 5.2, 5.3_
- [ ] 4.2 条件別の実測記録と低減確認
  - 条件名は通常・暗転・長時間不在・復帰直後・長時間監視に固定し、各条件で電力・復帰時間・精度を実測記録する（4spec共通の正準雛形は本specのdesign Testing Strategyに集約し、将来参照用とする。現時点で他specからの参照はなく、後続で他specに参照1行追加が必要）
  - 記録雛形（条件／電力／復帰時間／精度／比較根拠。測定できない項目は未計測と明記）に従い記録する
  - 実測値に基づき暗転時の低減を確認し、推定値を含めない
  - 測定できない項目を未計測として明記した記録が残る
  - _Requirements: 7.1, 7.2, 7.3, 8.1, 8.2_
