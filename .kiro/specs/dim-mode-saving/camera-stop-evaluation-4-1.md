# カメラ停止の評価記録（task 4.1）

本記録は Requirement 5（5.1, 5.2, 5.3）および design「Session / 評価手順／カメラ停止評価」に対応する、
暗転中のカメラ停止に関する評価観点・記録形式・現状（評価未完了 → 停止経路なし）の参照用記録である。
本フェーズでは停止実装を行わない（design Non-Goals／Out of Boundary「カメラ停止の実装（評価完了まで見送る）」）。

design Testing Strategy の「評価未完了時の停止経路の不存在」に対応する検証記録を兼ねる。
条件別の5条件実測（design「実測記録の正準雛形」：通常・暗転・長時間不在・復帰直後・長時間監視）とは別枠であり、
本記録は task 4.2 の実測記録に含めない。

## 現状：評価未完了 → 停止経路なし（5.1）

- 暗転中のカメラ停止に関する監視継続・復帰時間・検出精度への影響評価は未完了である。
- よって Requirement 5.1 に従い、カメラ取得を停止する経路を暗転系に作らない。
- `cameraManager.stop()` の呼出し点は以下の3点のみであり、いずれも暗転系ではない：
  - `stopMonitoring()`（ユーザーの明示停止）
  - `handleDidEnterBackground()`（背景退避）
  - `restartCameraPipeline()`（カメラ切替え時の再起動）
- 暗転系（`enterDimMode`／`exitDimMode`／`applyDimPowerStage`／`restoreDimPowerToNormalIfNeeded`／不在駆動 tick
  `dimPowerPolicy.tick` → 段階変化時のみ `applyDimPowerStage`）のいずれにも `cameraManager.stop()` の呼出しはない。
- 否定証明の再現手順：`rg -n "cameraManager\.(stop|start)" NekozeFix/Session/PostureSessionManager.swift`
  および `rg -n "stop\(\)" NekozeFix/Services/CameraSessionManager.swift` を実行し、
  停止呼出しが上記3点のみであること、暗転系に含まれないことを確認する。

## 評価観点（5.1 の「監視継続・復帰時間・検出精度への影響」に対応）

将来の実機評価では、以下の3観点を実測値のみで記録する。推定値は記録しない。

1. 復帰時間：停止状態からの復帰操作開始から、通常モードの監視状態へ戻るまでの時間（実機計測）。
2. 再開時の検出遅延：カメラ再開後、姿勢検知が通常水準に戻るまでの遅延（3秒連続確定判定の意味は変えない前提で確認する）。
3. 再開コスト：カメラ再開に伴う処理・電力面の実測コスト（開始失敗時の扱いは既存の権限・ライフサイクル則に従う）。

## 記録形式（未計測の明記・推定禁止）

評価完了までは全項目を未計測として残す。測定できるようになった項目から実測値＋条件を記入する。

```text
評価対象: 暗転中のカメラ停止
状態: 評価未完了（停止経路なし）
復帰時間: 未計測
再開時の検出遅延: 未計測
再開コスト: 未計測
監視継続への影響: 未計測
比較根拠: <通常監視との比較・再現条件（実測時のみ記入）>
```

- 実測していない省電力率・持続時間の推定値は記録に含めない（Requirement 7.2 の則を準用）。
- 測定できない項目がある場合は当該項目を未計測として明記する（Requirement 7.3 の則を準用）。

## 採用条件（5.2, 5.3）

- 5.2：暗転中のカメラ停止を採用する場合は、本記録様式による事前の影響評価記録に基づき、
  監視継続への影響を利用者に説明できる状態にすることを条件とする。評価記録なしの採用はしない。
- 5.3：カメラ停止を採用した暗転モード中であっても、復帰操作時には通常モードの監視状態へ復帰できることを条件とする。
  復帰経路（暗転解除・監視開始・フォアグラウンド復帰）での通常戻し則は task 3.2 の復帰時戻しに準じる。
