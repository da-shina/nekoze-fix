# セッション開始・停止と通知音の動作

## 概要

通知音は監視開始時にプリロードし、監視停止時に即座に停止する。人物検出と姿勢崩れの判定は即座に行われ、再通知は前回通知から30秒間隔とする。

## 詳細

- **通知音プリロード**: `startMonitoring()` 呼び出し時に `AlertPlayer.configureSession()` と音声ロードを実行。監視停止時に解放。
- **通知音再生**: `confirmedSlouch` 入場で即座に `playOnce`、その後前回通知から30秒間隔で `startRepeating` が動作。前の音が鳴っている最中に次の再生時刻になったら前の音を停止して新しい音を再生。
- **人物検出**: Vision が `nil` を返したら即座に `personMissing` と判定。
- **姿勢崩れ**: キャリブレーション中に（角度変化 > 5度 OR 人物検出途絶）で蓄積リセット。
- **再通知間隔**: 前回通知から30秒経過で次の通知（「0s, 30s, 60s...」ではなく「通知時点から30秒後」）。

## Considered Options

- プリロードタイミング: 起動時 vs 監視開始時 → メモリ効率のため監視開始時を採用
- 同時再生ポリシー: 前の音を停止して次を再生 → 重複を避ける
- 人物検出の遅延: ノイズ耐性 vs 応答性 → 即座判定を採用（人間の検出喪失はフレーム単位で起こりうる）
- 再通知基準: 確定時点から vs 前回通知から → 前回通知からとする方が人間の「30秒間隔」感覚に近い
- 元の輝度復元: UserDefaults vs プロセス内メモリ → 暗転は一時的状態なのでプロセス内メモリで十分
