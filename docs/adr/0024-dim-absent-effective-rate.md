# 暗転長時間不在の実効実行数による更なる低下

暗転時（推論10fps・Motion 15Hz）から長時間不在へ進む際、推論上限は上流選定範囲外の独自値を避けて10fpsに据置き、更なる低下はMotion 10Hzと既存の条件化・hop集約後の実効実行数で満たす。要件2.2の「推論実行頻度」は上限値ではなく実効実行数と解釈する。

## 詳細

- 段階別マッピング（Session側定数、`DimPowerPolicy`は段階のみ所有）：通常15fps/30Hz・暗転10fps/15Hz・長時間不在10fps/10Hz
- 不在しきい値は既定60秒（単調時計、実測で見直し）。変更は値型内定数のみでADR不要
- 人物信号はデバウンス済み（`updateState`確定後の`isPersonDetected`）のみ入力し、生検出は使わない
- 復帰経路（暗転解除・監視開始・フォアグラウンド復帰）で「輝度復元→通常段階→上限・頻度戻し」の順序固定、起停は触らない

## 検討した選択肢

- 推論5fps新設：削減は明確だが上流の選定範囲外の独自値となり境界違反（却下）
- 上限値で更なる低下を要求：10未満の受口が上流に存在せず、本specでの受口追加は境界外（却下）
- 生検出で不在計測：瞬断ノイズでタイマーが振動し長時間不在に到達しない（却下、デバウンス済みを採用）

## 今後の対応

- [ ] 不在しきい値60秒の妥当性を実測記録で見直す（design再検証トリガー）
- [ ] 通常・暗転・長時間不在・復帰直後・長時間監視の5条件で電力・復帰時間・精度を実測記録する（推定記載なし、未計測明記）
- [ ] 長時間不在時の Vision 負荷増（顔フォールバックにより推論あたり約2倍）への対応を別specで検討する。本ADRの「実効実行数で更なる低下を満たす」前提は Vision 負荷では成立していない（`absent-vision-cost-4-2.md`）
